# 2026-08-09 활동 일지

## hand_setting Stage 2 전환 구조

편 손에서 `pose_005` 관절 자세로 접근한 뒤 functional contact를 만드는 과정을
관측 차원 추가나 내부 latch 없이 두 개의 memoryless gate로 구성했다. actor observation은
기존 **101D**, action은 **20D** 그대로다.

```text
Stage 1 ready
  = pair_score >= 0.65
  and thumb_pivot_score >= 0.35

Stage 2 ready
  = Stage 1 ready
  and max(abs(q_all20 - q_ref_all20)) <= 5 deg
```

- Stage 2 전환에는 별도의 유지 step을 두지 않았다.
- `stage2_ready=1`인 동안에만 six semantic contact의 mean/min 보상이 활성화된다.
- 강한 16-joint acquisition guide는 Stage 2에서 꺼지고, all-20 reference prior는
  effective weight `8 -> 2`로 약해져 실제 접촉 자세를 찾을 여지를 남긴다.
- 현재 관절이 5도 범위를 벗어나거나 Stage 1 조건이 깨지면 Stage 2는 즉시 꺼지고
  강한 관절 유도가 다시 켜진다.

## 다음 학습 판정 순서

이번에는 구조를 더 바꾸지 않고 먼저 현재 gate로 `stage2_ready`가 실제로 켜지는지 확인한다.

우선 볼 TensorBoard 지표:

```text
stage1_ready
all_joint_reference_max_error
all_joint_within_5deg
stage2_ready
functional_contact_count / functional contact force
stage2_contact_mean / stage2_contact_min
thumb/index/middle/ring/little joint reference max error
```

판정은 다음처럼 한다.

1. `stage1_ready`는 켜지지만 `all_joint_reference_max_error`가 `0.08727 rad` 아래로
   내려가지 않으면, finger별 max error로 막는 손가락을 먼저 특정한다.
2. `stage2_ready`가 켜지고 contact 지표가 상승하면 현재 q-reference gate를 유지한다.
3. `stage2_ready`가 전혀 켜지지 않거나, 접촉을 만들면서 관절이 reference에서 벗어나 gate가
   반복해서 꺼지면 q-reference와 실제 contact 자세가 상충한다는 근거로 본다.
4. 그 경우 다음 A/B에서 Stage 2 전환을 **functional contact 기반**으로 바꾸는 방안을 검토한다.
   구체적인 contact threshold/progress 식은 이번 결과를 본 뒤 정하며 아직 구현하지 않는다.

즉 현재 실험의 1차 목적은 최종 6-contact 성공률보다 먼저 `stage2_ready`의 도달성과
안정성을 확인하는 것이다.

## 후속 변경 1 — hand_move 액션을 pose_005 기준 residual로 전환

`hand_move`의 손가락 action을 기존 current-joint residual에서 논문형 고정 reference
residual로 전환했다. action/observation 차원은 각각 **20D/103D로 유지**한다.

```text
이전:
q_target = q_current + 0.10 * action

현재:
q_target = q_pose005 + 0.30 * action
```

- `q_pose005`는 수동 파지에서 측정한 `PREGRASP_JOINT_POSITIONS`다. 접촉 preload용으로
  저장했던 `PREGRASP_JOINT_TARGETS`를 사용하지 않는다.
- current-joint residual은 매 policy step마다 현재 위치를 기준으로 다시 target을 잡기 때문에,
  외란이나 접촉으로 밀린 자세가 다음 target의 새 기준이 되어 파지가 서서히 ratchet/drift할 수 있었다.
- 고정 reference residual은 항상 검증된 파지 자세 주변으로 복원력을 만든다.
- `0.10 rad` 고정-reference 범위는 OPEN/CLOSE에 너무 좁을 수 있어 시작 A/B 범위를
  `+-0.30 rad`(`+-17.2 deg`)로 두고 joint-limit clamp는 유지했다.
- 기존 `CustomResidualJointActionCfg(scale=0.1)` 블록은 삭제하지 않고 바로 위에 주석으로
  보존해 한 블록만 바꾸면 원복할 수 있다.
- action shape는 같아 기존 checkpoint가 형식상 로드될 수 있지만 action 의미가 바뀌었으므로,
  성능 비교용 학습은 이전 checkpoint resume가 아니라 fresh run으로 시작한다.
- `hand_object`가 `hand_move` action cfg를 상속하므로 이후 두 skill은 같은 action 의미를 공유한다.

## 후속 변경 2 — hand_setting missing-16 guide를 best-so-far로 전환

위의 최초 memoryless Stage 1/2 설계를 학습한 결과, 병목은 Stage 1 자체가 아니라
Stage 1 이후 나머지 손가락을 `pose_005`로 보내는 구간이었다.

최근 `2026-08-09_19-07-55`의 핵심 지표:

```text
stage1_ready                 mean ~= 0.72, final ~= 0.92
all_joint_reference_max_error       ~= 2.11 rad
all_joint_within_5deg               = 0
stage2_ready                        = 0
functional_contact_count     mean ~= 2.69, final ~= 2.93 / 6
```

말단 관절의 PD target-actual 추종 오차는 약 `0.003~0.01 rad`로 작았지만, 정책이 일부
Joint3/4 target을 reference 반대편 음수 limit 쪽으로 냈다. 따라서 현재 병목은 actuator가
target을 못 따라간 것이 아니라, 손가락을 굽혀 스틱과 충돌하면 Stage-1 gate와 joint reward가
꺼지는 구조 및 먼 자세에서도 계속 지급되던 linear annuity의 local optimum으로 판단했다.

기존 strong guide는 다음 current-score 연금이었다.

```text
linear_score
  = 0.5 * mean(per_joint_linear_score)
  + 0.5 * min(per_joint_linear_score)

reward = current_stage1_gate * linear_score
weight = 100
```

오차가 `2.1 rad`여도 `joint_linear_range=2.5 rad`라 worst-joint score가 약 `0.16` 남아,
틀린 자세를 유지해도 매 step 양의 보상을 받을 수 있었다. 이를 다음 best-so-far 구조로
교체했다.

```text
stage1_unlocked |= stage1_ready

unlock 순간:
best_score = current_score
reward = 0

이후:
progress = max(current_score - best_score, 0)
best_score = max(best_score, current_score)
reward = stage1_unlocked * progress
```

- Stage 1은 최초 통과 후 one-way unlock된다. 이후 손가락 접촉으로 현재 Stage-1 gate가 잠깐
  꺼져도 missing-16 접근 신호가 사라지지 않는다.
- unlock 순간의 score를 기준선으로 seed하므로 Stage 1 이전에 만들어진 관절 progress를
  소급 지급하지 않는다.
- 자세를 망가뜨린 뒤 이전 최고점까지 돌아오는 왕복은 0점이며, 에피소드 최고 기록을
  실제로 갱신한 양만 지급한다.
- two-stick reference와 thumb-pivot current-state reward는 계속 살아 있어, latch 이후 anchor를
  버리는 행동에는 별도 이득이 없다. Stick drop termination도 그대로 유지한다.
- best-so-far는 에피소드당 score 최대 증가량만 지급하므로 per-step annuity weight와 직접
  비교할 수 없다. 30 Hz에서 최대 예산을 약 100으로 맞추기 위해 weight를 `3000`으로 두었다.
- 기존 `stage1_missing_joint_linear_reference(weight=100)` 전체 블록은 삭제하지 않고 주석으로
  보존했다. 새 best-so-far 블록만 주석 처리하고 기존 블록을 해제하면 즉시 원복 가능하다.
- 기존 all-20 exponential prior와 missing-16 exponential guide는 유지했다.
- 현재 q-reference A/B에서는 Stage-2 contact mean/min reward가 계속 주석 상태다. 먼저
  best score와 all-joint error가 실제로 개선되는지 검증한 뒤 contact 단계를 다시 연결한다.

추가 TensorBoard 지표:

```text
Episode_Reward/stage1_missing_joint_best_so_far
Metrics/hand_setting/stage1_unlocked
Metrics/hand_setting/missing_joint_best_score
```

우선 판정 순서는 `stage1_unlocked` 상승 여부 -> `missing_joint_best_score` 우상향 여부 ->
finger별 reference error 감소 -> `all_joint_reference_max_error < 0.08727 rad` 및
`stage2_ready` 활성 여부다. reward 의미와 내부 episode state가 바뀌었으므로 이 실험 역시
이전 checkpoint를 resume하지 않고 fresh run으로 비교한다.

## 후속 변경 3 — missing-16 best-so-far를 관절별 기록으로 분리

통합 best-so-far를 적용한 fresh run `2026-08-09_22-51-45`를 약 550 iteration까지
확인했다. 이전 annuity run보다 q-reference 오차는 개선됐지만 Stage 2에 도달하기에는
여전히 멀었다.

```text
지표                              이전 19-07-55     22-51-45
all_joint_reference_rmse          약 1.13 rad       약 0.96 rad
all_joint_reference_max_error     약 2.11 rad       약 1.83 rad
middle_joint_reference_rmse       약 1.21 rad       약 0.83 rad
all_joint_within_5deg             0                 0
stage2_ready                      0                 0
```

중지는 뚜렷하게 개선됐지만 검지·약지·새끼 RMSE는 여전히 약 `1 rad` 이상이었다. 원인은
기존 통합 score가 다음처럼 16관절을 먼저 한 값으로 축약한 뒤 그 값 하나의 최고 기록만
추적했기 때문이다.

```text
old_score = 0.5 * mean(score_1 ... score_16)
          + 0.5 * min(score_1 ... score_16)

old_progress = max(old_score - old_best, 0)
```

최악 관절이 그대로면 min 절반은 개선되지 않고, 다른 관절 하나의 개선도 mean 절반에서
`0.5 / 16 = 3.125%`만 반영된다. 이를 16개 관절이 각각 독립적인 최고 기록을 가지도록
교체했다.

```text
score_j = clip(1 - abs(q_j - q_ref_j) / 2.5, 0, 1)

Stage 1 unlock 순간:
best_j = score_j
reward = 0

이후:
progress_j = max(score_j - best_j, 0)
best_j = max(best_j, score_j)
reward_raw = mean(progress_1 ... progress_16)
```

- Stage-1 one-way unlock과 unlock 순간 baseline seed는 그대로다.
- 관절별 progress를 합산한 뒤 **평균**하므로 raw reward의 에피소드 최대 증가량은 여전히
  `1`이다. 따라서 weight `3000`, 30 Hz 기준 최대 예산 약 `100`은 바꾸지 않았다.
- 한 관절의 개선이 다른 관절의 현재 오차나 worst-joint score 때문에 사라지지 않는다.
- Stage-2의 live all-20 `5 deg` 조건은 그대로이므로, 서로 다른 시점에 개별 기록만 세우고
  최종 동시 자세를 만들지 못한 정책은 Stage 2를 통과할 수 없다.
- 기존 all-20 exponential prior와 missing-16 exponential guide도 그대로 유지했다.
- reward 의미가 다시 바뀌었으므로 이 변경 역시 `22-51-45`에 resume하지 않고 fresh run으로
  비교한다.

TensorBoard에는 기존 aggregate 지표를 유지하고, index/middle/ring/little의 Joint1~4마다
현재 linear score와 episode best score를 추가했다.

```text
Metrics/hand_setting/<finger>_joint<1..4>_current_linear_score
Metrics/hand_setting/<finger>_joint<1..4>_best_linear_score
```

따라서 새 지표는 총 `16 joints x 2 = 32`개이며 기존 다음 지표도 유지된다.

```text
missing_joint_best_score
all_joint_reference_rmse
all_joint_reference_max_error
stage1_unlocked
stage2_ready
```

`22-51-45`의 기존 event 파일을 직접 확인했을 때 reference metric tag는 실제 파일에
남아 있었다. 새 관절별 tag는 코드를 다시 로드한 fresh process가 episode log를 기록한
뒤부터 TensorBoard에 나타난다. 변경 후 검증은 사용자 실행 전용 원칙에 따라
`py_compile`, 정적 구성 대조, `git diff --check`까지만 수행했다.
