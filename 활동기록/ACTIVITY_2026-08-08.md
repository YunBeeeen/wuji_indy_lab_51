# 2026-08-08 활동 일지

## 요약

**외란(stick disturbance)이 파지를 강화한다는 것이 실증됐다.** `full_contact` 0.335 →
0.948, `min_functional_force` 0.107 → 0.449 N. 외란 세기에 대한 **용량-반응 관계**가
확인되어 인과로 볼 근거가 생겼다.

사수님이 처음 제안하신 방향이 맞았고, 내가 "이미 깨진 상태를 충분히 겪으니 외란은
불필요하다"고 한 판단이 틀렸다.

## 1. Stick disturbance 구현

`hand_move`에 external force pulse 이벤트를 추가했다. `hand_grasp` 베이스라인은
건드리지 않았고, 보상·관측·액션·종료도 그대로다.

```
hand_move_mdp.py      class StickDisturbance(ManagerTermBase)
hand_move_env_cfg.py  DISTURBANCE_TIME_RANGE_S / _DURATION_S / _FORCE_RANGE_N / _PROBABILITY
                      HandMoveEventCfg.stick_disturbance
managers.py           _configure_disturbance_metrics / _log_disturbance_metrics
```

### 동작
```
리셋 시 env 마다 독립 샘플
  target       Stick1 / Stick2   50:50
  start_time   5.5 ~ 12.0 s      균등
  magnitude    force_range 내 균등
  direction    구면 균등 -> pulse 시작 시 shaft 성분 제거 (transverse)

pulse   0.10 s = policy step 3회 = physics step 12회
        월드 좌표 고정, 에피소드당 1회 (latch)
```

### External wrench lifecycle (설치 소스 확인)
- `permanent_wrench_composer` 는 **persistent** 버퍼. `write_data_to_sim` 이 매 물리
  스텝 재적용한다 (`rigid_object.py:134-152`). 감쇠 없음.
- `set_external_force_and_torque` 는 이 빌드에서 **deprecated** — 호출마다 warning 을
  찍고 composer 로 위임한다 (`rigid_object.py:442`). composer 를 직접 쓴다
  (public property, `rigid_object.py:113`).
- 매 스텝 **전체 버퍼를 0 포함해 다시 쓴다.** pulse 종료가 별도 코드 경로가 아니라
  상태 머신이 `active` 를 내리면 다음 write 가 0 을 넣는 구조 — 놓칠 teardown 이 없다.
- `RigidObject.reset` 도 composer 를 비운다 (`rigid_object.py:126-132`). 이중 안전.

### 왜 `interval` 이벤트인가
pulse 는 duration 이 있어 매 스텝 실행이 필요한데, 이벤트 모드 중 매 스텝 도는 건
`interval` 뿐이다. `interval_range_s=(0,0)` 으로 매 스텝 발화시켜 **훅으로만** 쓰고,
disturbance 스케줄은 term 자체의 per-env state 가 에피소드 시계로 판단한다. 그래서
"에피소드당 1회" 가 interval 메커니즘에 의존하지 않는다.

## 2. 외란 실험 결과 — 용량-반응

보상 설정이 **완전히 동일**하고 외란만 다른 세 런:

```
                        외란 없음   0.02~0.1 N   0.3~1.2 N
iteration                   751        3845        6004
full_contact              0.335       0.996       0.948
min_functional_force      0.107       0.264       0.449   <- 단조
functional_contact_min    6.522      19.765      18.802
stick1_pivot_error [mm]  10.345       6.856       3.833   <- 단조
mean_reward             454.636     773.946     759.758
```

**`min_functional_force` 와 `stick1_pivot_error` 가 외란 세기에 단조로 반응한다.**

### iteration 교란 배제
"오래 돌려서 좋아진 것" 이 아니다. 외란 없는 고-iteration 런들:
```
외란 없음  it 2653   full_contact 0.03~0.98 진동
외란 없음  it 4983   full_contact 0.583
외란 0.02  it 3845   full_contact 0.996
외란 0.3   it 6004   full_contact 0.948
```
it 4983 에서 외란 없이 0.583 이 천장이다.

### 메커니즘
`functional_contact_min` 이 min 게이트라 **접촉 하나만 끊겨도 20 weight 가 통째로 0**
이다. 외란이 그 사건을 자주 만드니 정책 입장에서 **여유를 크게 두는 게 이득**이 된다.
내가 "min 절벽이 복원을 막는다"고 걱정한 그 구조가, 외란과 결합하면 **강한 예방 압력**
으로 작동한다.

### 진단 지표 정상 동작
```
applied_fraction     1.000        stick1_fraction    0.468 / 0.499  (50:50)
contacts_before      6.000/5.966  min_contacts_after 5.674 / 5.483
recovered            1.000/0.946  recovery_time_s    0.051 / 0.058
```

## 5. 확인된 사실들

### `full_contact` 는 진동한다 (0.03 ~ 0.98)
```
이전 보상 it 1050~2650   0.03 0.65 0.41 0.91 0.09 0.05 0.34 0.92 0.98 0.58 0.23
```
**0.91~0.98 까지 갔다가 무너지고 다시 올라온다.** 즉 능력도 복원 능력도 있고, **유지를
못 하는 것**이 문제였다. 이 진동이 외란 도입 후 사라졌다(0.948~0.996).

### 루트 PD 는 원인이 아니다
```
                              부유,개폐없음   부유+개폐
orientation_error_current       0.579 deg     0.507 deg
full_contact                    0.917         0.335
```
개폐를 켜도 루트 추종 오차는 오히려 줄었다. **루트 진동으로 접촉이 깨진다는 가설은 기각.**

### `hand_grasp` 는 왜 min 으로도 됐나
```
                fix_root_link   개폐   full_contact
hand_grasp          True        있음      0.775
hand_move(파지)     False       없음      0.917
hand_move(개폐)     False       있음      0.335
```
**부유 루트와 개폐가 겹칠 때만 무너진다.** 고정손은 개폐 반작용을 세계가 받아준다.

## 6. 미적용 / 보류

### `force_scale` 0.10 -> 0.8 (보류)
```
현재 min_functional_force = 0.449 N
force_scale 0.45 이하는 전부 포화라 no-op. 0.8 이상이어야 gradient 가 생긴다.
```
보류 사유 셋:
1. 0.8 이면 `functional_contact_min` 실현값이 18.8 -> 약 10 으로 반감
2. Stick1 을 쥐는 세 손가락은 벌리려면 힘을 빼야 하는데, `open_tip_gap` 이 겨우
   0.276 -> 1.952 로 7배 좋아진 참이라 다시 막을 위험
3. 시뮬 말단 관절 토크가 실기의 1.3~3.4배라, 파지력을 더 요구하면 **시뮬에서만 되는
   정책**이 될 위험

**판단 기준**: 외란 힘을 1.0~3.0 으로 올려서 `min_functional_force` 가 계속 오르면
외란 레버가 유효한 것이고 `force_scale` 은 불필요. 0.45 근처에서 정체하면 그때 근거가
생긴다. (외란 쪽은 아직 단조 상승 중이라 포화 안 함)

### 외란 힘이 아직 약함
```
0.709 N 에서 min_contacts_after 5.483  (0.5개 손실)
목표는 1~2개 손실
recovery_time_s 0.058 s < duration 0.10 s   <- 펄스가 끝나기 전에 회복
```
보완 레버 (효과 순):
1. **적용점을 팁으로** — `positions=(0, 0.09, 0)`. 지금은 무게중심이라 스틱이 통째로
   평행이동하고 6접촉이 같이 저항한다. 팁이면 지렛대가 되어 손끝 접촉을 떼어낸다.
   "테이블에 부딪힘" 시나리오와도 물리적으로 일치. **한 줄.**
2. 크기 1.0~3.0 N 상향
3. duration 연장 — 준정적 영역이라 끊기는 **개수는 안 늘고** 깨진 시간만 늘어난다
4. 방향 편향 / 토크 (v2)

### `hand_object` 의 외란 설정 (미결정)
`HandObjectEventCfg` 가 `HandMoveEventCfg` 를 상속해 외란이 그대로 들어간다. 그런데
에피소드가 9.0초라:
```
발동 비율 = (9.0 - 5.5) / (12.0 - 5.5) = 53.8%
발동 구간 = 기둥이 빠지고 큐브를 맨손으로 버티는 hold 구간
```
hand_move 에서 "파지 여유를 키우는 정규화" 로 작동한 것과 성격이 다르다 — 여기서는
**평가 구간을 직접 방해**한다. 재시작 전에 `probability` 나 `time_range` 를 따로
잡을지 결정 필요.

## 목표 정리 (사수님 확인)

외란의 목적은 세 가지 실패 모드 방지:
1. **중력으로 스틱이 무너짐** -> 외란이 아니라 **회전 커리큘럼(3단계)**. 회전 범위가
   0 이면 중력이 손 기준으로 늘 같은 방향이라 정책이 상수로 외운다.
2. **테이블에 부딪혀 틀어짐** -> **팁 적용점**이 정확히 이 시나리오
3. **OPEN 중 약지 이탈** -> 외란이 직접 못 고치지만, **여유를 키워 이미 해결됨**
   (`ring_tip` 0.476 N 이 최약이던 것이 `min_functional_force` 0.449 로 상승)
