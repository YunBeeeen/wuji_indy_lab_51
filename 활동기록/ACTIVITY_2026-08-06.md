# 2026-08-06 활동일지 — hand_object 학습환경 구현, tip gap σ 분석

## 1. hand_object 환경 신설 (hand_move fine-tuning용)

목표: `hand_move` 정책을 이어받아 fine-tuning → CLOSE에서 두 젓가락으로 1cm 큐브를
실제 접촉력으로 집고, 손을 움직여도 안 떨어뜨리게.

### 결정 사항 (구현 전 확정)
- **yaw 축 = 손 local z** (`hand_move`의 `range_z`와 동일). `q_goal = quat_mul(q_start, q_delta)`.
- **task ID는 `hand_object` 하나** — train/play/calibrate로 나누지 않음. `hand_move`와 같은 방식으로
  세 command의 manual override + `play.py --manual_root`로 갈림.
- **기둥(support) 하강은 CommandManager**(30Hz)에 구현.
- **미측정 3값은 `None`으로 비워둠** + 명확한 fail-fast.

### 에피소드 스크립트 (7초, 30Hz)
```
Phase 1  0.0-0.5s  step   0- 15   OPEN, 자세 안정
Phase 2  0.5-2.0s  step  15- 60   OPEN + yaw SLERP
Phase 3  2.0-2.5s  step  60- 75   OPEN, settle
Phase 4  2.5-3.5s  step  75-105   CLOSE, 파지 형성
Phase 5  3.5-4.0s  step 105-120   CLOSE, 기둥 20mm 하강 (15스텝 × 1.33mm)
Phase 6  4.0-7.0s  step 120-210   CLOSE, hold  ← 평가 구간
```

(보상 예산 점검은 아래 별도 절 참조. drop penalty·over-force penalty 는 의도적으로 없음.)

### 보정 완료 (2026-08-06, GUI 수동 조작으로 측정)

`play.py --manual_root` 로 띄우고 키보드로 손을 큐브까지 몰아 자세를 잡은 뒤 `P` 로 읽음.

```python
HAND_OBJECT_TARGET_ROOT_POS_E = (0.0780, -0.0470, 0.3700)   # 스폰 대비 15.9cm 이동
HAND_OBJECT_TARGET_EULER_RAD  = (0.0934, 0.3472, -1.0331)   # deg (+5.35, +19.89, -59.19)
HAND_OBJECT_CUBE_POS_E        = (0.1468, 0.0865, 0.4114)    # = 그 자세의 tip 중점
HAND_OBJECT_SUPPORT_POS_E     = (0.1468, 0.0865, 0.2030)    # 바닥~큐브 밑, 기둥 높이 406mm
HAND_OBJECT_FORCE_SATURATION_N = 0.05   # 여전히 PROVISIONAL
```

손 스폰과 큐브가 둘 다 고정이라 **보정 대상은 "손이 날아갈 목표 root pose" 하나**뿐이고,
큐브 위치는 그 자세에서의 distal tip 중점으로 따라온다.

**설계 변경(중요)**: 원래는 yaw 하나만 보정하고 root 위치는 스폰 고정이었다. 그러면 tip 이
팜 주위로 호만 그려서 12cm 떨어진 큐브에 도달하지 못한다. 사용자 지적으로 **이동+회전**으로
바꿈 — `HandRootHoldActionCfg.position_command_name` 을 신설해 위치도 커맨드 궤적을 따르게 했다
(미설정이면 기존 동작 그대로라 `hand_move` 무영향).

**yaw-only 안 검토 기록** ("이동이 너무 많다"는 지적에 계산해 본 것): root 를 스폰에 고정하면
tip 중점이 yaw 의 닫힌 함수가 된다. x 는 어느 yaw 에서도 0.1134 고정(회전축이 월드 +x).
압착축 z성분이 0 에 가까울수록 중력을 마찰로 받치기 유리한데 local-z −80~−90° 가 그렇다.
최종적으로는 이동을 포함한 위 자세를 채택.

| yaw | tip 중점 | closing z | 기둥−손 |
|---|---|---|---|
| 0° | (0.1134, +0.0223, 0.6043) | −0.569 | 4.1mm ✗ |
| −60° | (0.1134, +0.1015, 0.5329) | −0.269 | 45.2mm |
| −86° | (0.1134, +0.1056, 0.4851) | −0.022 | ~44.8mm |
| −90° | (0.1134, +0.1043, 0.4777) | +0.018 | 44.3mm |
| −120° | (0.1134, +0.0792, 0.4285) | +0.300 | 23.1mm ✗ |

### 이동 궤적을 2단계로 (사용자 요청)

한 직선으로 가면 큐브에 대각선으로 접근하면서 **동시에 회전**해 tip 이 큐브 자리를 옆으로
쓸고 지나간다. 그래서 경유점을 하나 뒀다.

```
1단계 (move 창의 앞 50%)  스폰 높이 z=0.5 유지, 방향 회전 + x,y 정렬
2단계 (뒤 50%)            방향 고정, 순수 z 하강 0.5 → 0.370
```

- **경유점은 계산으로 나온다** — 목표 위치의 z 만 스폰 z 로 바꾼 값. 상수를 하나 더 두면
  어긋날 여지가 생겨서 파생시켰고, 덕분에 2단계가 순수 수직 하강인 게 구조적으로 보장된다.
- **회전은 1단계에서 끝난다.** 부모는 전체 창에 걸쳐 회전시키므로 `_update_command` 를
  오버라이드해 회전만 `alpha/approach_fraction` 시계로 돌렸다.
- `approach_fraction = 0.5` 로 조절 가능. 검증: 1단계 z 이탈 0.000mm, 2단계 x,y 이탈 0.000mm.

### 보상 예산 점검 (7초 에피소드 기준)

```
상속 dense 합                                    819
  joint_reference 14 / stick1_pivot 70 / stick2_reference_pose 105
  open_tip_gap 50 / close_tip_gap 90 / functional_contact_min 140
  mode_grasp_stability 350
  (success 30000 = 한 방 1000점이지만 hand_grasp 실측상 계속 0이라 제외)

큐브 합                                         1200
  bilateral_cube_force  100 × 4.5s = 450
  cube_relative_stability 50 × 3.0s = 150
  cube_hold             200 × 3.0s = 600
```

- 큐브 / 상속dense = **1.47배**. 큐브 파지가 목적이니 큰 게 맞고, `cube_hold` 600 은
  `close × retracted × force × stability` 곱이라 진짜 잡지 않으면 못 받는다.
- **주의**: `bilateral_cube_force` 450 은 **젓가락 파지 유지에 게이트가 없다**(CLOSE 모드만 봄).
  "젓가락을 흘리면서 큐브만 짓누르는" 행동의 손익이 얻음 450 vs 잃음 490
  (`functional_contact_min` 140 + `mode_grasp_stability` 350) 이라 여유가 8% 뿐.
  `bilateral / functional_contact_min = 3.21배`.
  → 100 을 50 으로 낮추면 여유 2.2배가 되지만, **일단 100 유지로 시작**하고
  `Metrics/hand_grasp/functional_contact_count` 가 5.5 아래로 떨어지면서
  `Metrics/hand_object/bilateral_force_score` 가 오르면 그때 낮추기로 함.

### 구현 중 걸린 것 (CLAUDE.md 에도 기록)
- `configclass` 는 **상속받은 property** 를 처리 못 함. `_custom_post_init` 이
  `obj.__class__.__dict__` 만 보므로 부모의 property 를 못 알아보고 setattr 시도 →
  `AttributeError: property 'slerp_end_time_s' ... has no setter`. 자식에 재선언으로 해결.
- `configclass` 클래스는 `Cls.algorithm` 접근 불가(dataclass 필드). `__post_init__` 에서
  고치는 것은 더 위험 — deepcopy **이전**에 실행돼 공유 기본 객체를 오염시켜 HandGrasp/
  HandMove/HandSetting 의 LR 까지 같이 바뀜. 블록 전체를 명시 선언으로 해결.
- command term 들은 모듈 스케줄의 **복사본**을 들고 있음. 모듈 객체만 고치면 반영 안 됨.
- **위치 궤적을 넣자 키보드 이동키(I/K/J/L/U/O)가 죽었다.** 액션 term 의 위치 목표 버퍼를
  매 물리 스텝 커맨드 값으로 덮어쓰는데, 키보드가 바로 그 버퍼에 쓴다. 회전키는 커맨드
  버퍼에 직접 써서 멀쩡했던 게 진단을 늦췄다. 수동 모드에서 `target_pos_w` 가 `None` 을
  반환하게 해 해결(자세 쪽 `_scripted_target_quat` 와 같은 패턴).
- **`env.require_calibration=false` 가 첫 리셋을 못 막았다.** 생성 시점 가드만 껐고 스크립트
  궤적의 `_resample_command` 가 또 raise. 그 리셋은 `RslRlVecEnvWrapper.__init__` 안에서
  일어나고 manual override 는 그 뒤 `attach()` 에서 켜지므로 보정 세션이 시작조차 못 했다.
  → 미보정이면 경고만 하고 스폰 자세 유지. play 는 아예 가드를 자동으로 끄게 함.

## 2. hand_grasp OPEN/CLOSE tip gap σ 분석

"open/close 자세가 잘 안 나온다"에 대한 구조 분석.

### σ가 적용되는 구조
```python
# mdp.py: mode_tip_gap_tracking  (= open_tip_gap / close_tip_gap, 같은 함수를 2번 등록)
mode_gate * exp(-|gap-target|/sigma - lateral/lateral_sigma - axial/axial_sigma)
```
- `mode_gate`는 커맨드 **one-hot(0/1)** — 모드 전환만 담당, σ와 무관
- 셋이 한 exp 안이라 **곱(AND)**. `exp(-|e|/σ)` 라플라시안
- **gap σ는 두 군데**: `open/close_tip_gap.sigma`(w=20씩) + **`mode_grasp_stability.gap_sigma`(w=50)**
- `mode_grasp_stability` 안의 변수명 `mode_gate`는 misnomer — one-hot이 아니라 σ tolerance 커널.
  모드에 따라 `target_gap`만 20mm↔0mm로 블렌딩되고 항은 항상 켜져 있음

### 장축(axial) 항 실측 (pose_005 기하를 numpy로 재현, reset axial = -4.8016mm로 cfg 상수와 일치)
```
회전θ   gap      axial오차   axial배수   OPEN항   CLOSE항
-6.0°   0.00mm   1.226mm     0.783      0.014    0.764
 0.0°  13.41mm   0.000mm     1.000      0.268    0.069   ← reset
+3.0°  21.26mm   0.000mm     1.000      0.777    0.014
+5.0°  26.50mm   0.227mm     0.956      0.259    0.005
```
- OPEN 방향(0→3°)에서 axial 배수 **0.99~1.00 = 사실상 무영향**
- CLOSE 완전 폐합에서만 **0.78 (-22%)** → 꽉 닫을수록 손해, CLOSE 최적점이 gap 0이 아니라 θ≈-5.5°로 밀림
- 원인: 전 구간 axial 스윙 폭이 **1.2mm**뿐인데 σ가 **5mm** → 제약 역할은 못 하면서 CLOSE만 깎음
- 그리고 **reset에서 정확히 최댓값 1.0** — 08-05 hand_setting 교훈과 같은 형태

### σ를 낮출 때의 트레이드오프
```
σ_gap    OPEN@reset(6.6mm)  CLOSE@reset(13.4mm)  목표±1mm  목표±0.5mm
5.0mm       0.267              0.0686             0.819     0.905
3.0mm       0.111              0.0115             0.717     0.847
2.0mm       0.037              0.0012             0.607     0.779
1.0mm       0.001              0.000002           0.368     0.607
```
정밀도는 오르지만 **출발 신호가 같이 죽음**. 특히 CLOSE는 reset에서 13.4mm를 움직여야 하는데
σ=2mm면 0.0012로 사실상 평지.

### 채택안 (사용자 판단)
`open/close_tip_gap.sigma`는 5mm 유지(캡처/트리거 보존), **`mode_grasp_stability.gap_sigma`만 조임**
→ coarse/capture와 fine/converge를 항 추가 없이 2단 분리.
마지막 1mm 구간 보상 차이 `+0.086 → +0.537` (**6.2배**), 오차 0.5mm 지점 기울기 181→607 /m (3.4배).

**실제 적용값**: `hand_grasp_env_cfg.py:559` `gap_sigma 0.005 → 0.001` (세션 밖에서 적용됨).
`hand_object`도 이 보상을 상속하므로 같이 영향받음.

**예측되는 부작용 (미검증)**: reset에서 `mode_grasp_stability`가 공급하던 gap 압력(전체의 55~71%)이
0이 됨 → 캡처가 죽으면 `open/close_tip_gap` weight를 20→45로 올릴 것.
아래 신설 메트릭으로 바로 보임 — **에러가 안 줄고 평평하면 캡처가 죽은 것**.

### 참고: success가 진짜 병목
예산의 85%(`success` w=30000 ≈ 6000점)가 하드 리밋 `tip_gap_error_limit=0.0005`(**±0.5mm**,
회전각 0.2° 수준) + `angular_speed_limit=3.0`(실측 93% 초과)에 막혀 `2026-08-06_00-12-28` 런에서
처음부터 끝까지 0.0. σ를 아무리 조여도 여기 못 닿으면 그대로 0. **미조치**.
