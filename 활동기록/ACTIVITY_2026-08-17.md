## 1. `hand_real`의 현재 sim-to-real 계약

- actor observation은 **105D**다.
  - normalized joint position history `[previous,current]`: 40
  - current fingertip palm-frame xyz: 15
  - Stick1/2 palm-frame `xyz+wxyz` history: 14+14
  - 현재 상태를 만든 직전 clipped action: 20
  - OPEN/CLOSE one-hot: 2
- Stick quaternion은 local `+Y` 주위 90° 사각 단면 대칭 네 개 중 reference-nearest
  branch를 선택하고 `w>=0`으로 canonicalize한다. reward/success orientation은 여전히
  directed local `+Y` shaft axis만 평가하므로 특정 shaft roll을 강제하지 않는다.
- active current-joint residual action scale은 Joint1/2 `0.10 rad`, Joint3 `0.20 rad`,
  Joint4 `0.15 rad`다. 20개 Kp/Kd와 URDF per-joint effort limit은
  `hand_real_env_cfg.py`의 task-local table을 쓴다.
- 현재 Joint4 Kp는 thumb/index/middle/ring/little 순서로 `1.0/1.3/1.3/1.3/1.15`다.
- Stick1 reference axial 5 mm A/B 상수는 `0.0`으로 원복되어 reset/reference/pivot 모두
  기존 기하를 사용한다.

## 3. fixed-base Wuji MuJoCo deploy stack

- `mujoco_deploy/`를 현재 105D `hand_real` 계약에 맞춰 backend-neutral common policy
  plumbing과 MuJoCo backend로 분리했다.
- 공식 Wuji Hand 1 RIGHT description commit
  `06e5f14cdd1d5fad0a666ca463a668bf609f9534`를 고정해 사용한다.
- scene은 fixed `right_palm_link`, 20 hinge/20 position actuator이며 Indy7이 없다.
- policy joint order↔MuJoCo qpos/dof/actuator는 숫자 순서를 신뢰하지 않고 이름으로 strict
  mapping한다.
- physical/observation/command limit을 분리했다. observation normalization은 official
  nominal range, command는 같은 range에 다섯 Joint4 target lower `0 rad` override를 쓴다.
- action은 `clip(raw,-1,1)` → actual-radian current-joint residual → command limit clamp
  순서다. action scale은 Isaac과 같은 Joint1/2 `0.1`, Joint3 `0.2`, Joint4 `0.15`다.
- policy 30 Hz, MuJoCo physics 120 Hz, 한 target을 정확히 네 physics step 유지한다.
- 두 7×180×7 mm, 10 g Stick, D435 RGB calibration, ArUco provider, stale-pose safe stop,
  approximate physical-testbed viewer까지 추가했다.
- `RealWujiBackend`는 SDK/handedness/encoder order·sign·zero/watchdog/firmware position-control
  의미가 검증될 때까지 의도적으로 construction을 거부한다. 현재 코드는 실물 명령을 보내지 않는다.
- `VALIDATION_REPORT.md` 기준 common+MuJoCo+rendered-vision test 21개, 20-joint 단독 명령,
  30/120 Hz backend smoke와 stale perception safety gate가 통과했다.

### 좌표계와 변환 계약

```text
Marker frame:
  +X = 인쇄 마커 오른쪽
  +Y = 인쇄 마커 위쪽
  +Z = 마커 앞면 바깥 normal

Canonical Stick frame:
  origin = 180 mm Stick geometric center
  +Y = tail -> tip
  +Z = Marker0 outward normal
  +X = right-handed completion
```

Marker0과 Stick 축을 같게 두므로 `R_M0_S=I`이고:

```text
p_M0_S = [0, +0.090, -0.0035] m
T_C_S  = T_C_M0 @ T_M0_S
```

ID1 offset은 손으로 45°를 가정하지 않고 pair calibration으로 자동 생성한다.

```text
p_M0 = T_M0_M1 @ p_M1
T_M1_S = inverse(T_M0_M1) @ T_M0_S
T_C_S  = T_C_M1 @ T_M1_S
```

따라서 ID0 또는 ID1 어느 하나만 보여도 같은 Marker0-defined Stick center와 quaternion을
계산할 수 있다.

## 7. MuJoCo Camera2 높이/각도 후보 검사와 최종 역할 결정

추가 D435 후보를 Hand/Palm `+Y` 쪽에 두고 현재 flush ID0--ID3 marker와 exact
1280x720 intrinsics로 렌더한 뒤 OpenCV ArUco 검출을 검사했다. Hand+Stick assembly는
Palm `Z` 기준 `-90..0 deg`로 함께 회전시켰다.

- 비교용 45 deg 하향, Base 높이 0.36 m: 5 deg sweep `17/19`
- 비교용 57.5 deg 하향, 높이 0.38--0.40 m: `19/19`
- 비교용 60 deg 하향, 높이 0.38--0.43 m: `19/19`
- 60 deg/0.40 m의 1 deg dense sweep: `91/91`

그러나 사용자는 물리 bracket 설치가 쉬운 **하강각 0 deg(완전 수평)**를 선택했다.
이에 Camera2의 책임을 full-workspace tracker가 아니라 reset에서 두 stick의 tail marker
ID0/ID2를 확인하는 보조 카메라로 좁혔다. MuJoCo reset에서 추출한 marker 중심은:

```text
ID0 Base xyz = [0.121009, 0.061799, 0.072649] m
ID2 Base xyz = [0.129380, 0.049104, 0.047509] m
```

따라서 설치 후보 optical center는 Base `[X,Y,Z]=[0.125,0.200,0.060] m`, optical
forward는 `-Base Y`, 하강각은 정확히 `0 deg`로 두었다. reset/Palm-Z 0 deg에서
Camera2 단독 ID0+ID2 동시 검출은 PASS다. 반면 같은 수평 카메라는 5 deg 간격 전체
회전 sweep에서 `7/19`만 동시 검출하므로 full-range 보장으로 기록하면 안 된다.

구현/재현:

- `mujoco_deploy.scene_contract`: Camera2 candidate height/side/Z/angle named constants
- `right_with_tip_sites.xml`: 위 reset-tail candidate pose를 기본 Camera2 pose로 기록
- `mujoco_deploy.tools.sweep_camera2_mount`: `--down-angle`, `--side-y`, `--heights`,
  `--angles` 후보 sweep 지원
