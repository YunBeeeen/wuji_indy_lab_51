## 파지 안정성 실험 실패 판정과 활성 코드 리셋

- 오늘의 tip-only cage, 좁은 fingertip region, maintained proximity gate 실험은
  “손끝을 실제 물체 표면까지 오므린 안정 파지”를 만들지 못한 것으로 판정함.
  - tip-only 가상선도 멀리 떨어진 두 tip 사이를 물체가 가로지르면 cage가 열리는 false positive가 남음.
  - 좁은 region progress는 순간 접근은 보상하지만 그 위치의 지속 유지를 보장하지 못함.
  - maintained gate를 추가해도 이 시점에는 여러 구조 변경이 겹쳐 원인 분리가 어려웠고,
    기존 성공 운반 능력까지 잃을 위험이 커짐.
- 따라서 파지 안정성 보상 실험을 더 누적하지 않고, **활성 코드를 마지막으로 실제 성공했던 run 구성으로
  리셋**하기로 결정함. 여기서 리셋은 저장된 성공 run을 삭제한 것이 아니라 새 실험 변경을 되돌린 것임.
- 실패 실험의 소스와 maintained 함수는 backup/비활성 코드로 보존해 이후 단일변수 검증에 재사용 가능함.
- 다음 문제를 arm 접근·운반과 분리하기 위해 방향을 바꿈:
  - Indy 팔을 제거함.
  - 손바닥이 하늘을 보는 Wuji hand만 고정 배치함.
  - 두 젓가락을 이미 손바닥 위에 놓음.
  - 먼저 손가락만으로 표준 파지 자세와 이후 open-close가 가능한지를 검증함.

## `hand_grasp` 표준 파지 탐색 계획 — simulation only

- 실제 Wuji에서 파지 자세·관절각을 측정해 시뮬레이션으로 옮기는 방식은 사용하지 않음.
  기준 파지 `q_ref`와 두 stick의 palm-relative pose를 **시뮬레이션 안에서만** 찾음.
- 2022 `Learning to Use Chopsticks in Diverse Gripping Styles`의 표준 fingertip topology를
  Wuji용 출발점으로 사용함.
  - 필수: `stick1`에 엄지·검지·중지 fingertip 접촉.
  - 필수: `stick2`에 약지 fingertip 접촉.
  - 필수 anchor: `stick2`가 엄지–검지 사이 valley에 실제 물리 접촉하고 palm 기준 slip이 낮아야 함.
  - 형상 의존 보조 접촉 후보: 엄지 중간마디–`stick2`, 검지 중간마디–`stick1`.
  - 새끼는 초기에는 자유로 두며, 보조 접촉 두 개도 처음부터 success 필수조건으로 강제하지 않고
    metric으로 기록한 뒤 안정 후보에서 반복적으로 나타날 때만 승격함.
- valley는 파지 개구부 법선이나 가상 cage로 정의하지 않음.
  `palm_link`, `finger1_link1`(엄지 기저), `finger2_link1`(검지 기저)의 실제 collision/contact와
  `stick2` 중심선의 palm-frame 위치 및 상대속도로 판정함.
- **다음 작업의 우선순위는 collision 검증이 IK보다 먼저임.**
  1. 1-env 또는 소규모 병렬 probe로 `stick1`–`stick2` 충돌, `stick2`–valley 실제 접촉,
     닫힘 각도 sweep에서 tip이 먼저 닿는지, handle/pivot 충돌·침투·반발·마찰 고착 여부를 확인.
  2. 물리적으로 가능한 `stick2` valley pose와 `stick1` 상대 pose 후보를 고정한 뒤,
     필수 fingertip 접촉을 만족하는 Wuji 20관절 IK 후보를 생성.
  3. 각 IK 해를 자유로운 두 rigid stick과 함께 PhysX에서 1~2초 static hold 평가.
     필수 접촉 유지, valley anchor, palm-frame slip, drop, penetration, torque saturation을 보고
     안정 후보만 `q_ref_closed`로 저장.
  4. 보조 중간마디 접촉 A/B와 open-close는 안정적인 closed `q_ref`가 나온 뒤 검증.
- IK는 파지 안정성을 직접 보장하는 최종 판정기가 아니라, 지정 contact topology를 만족하는
  기하학적 후보 생성기임. 최종 자세 선정은 PhysX contact/slip/torque/drop 평가가 담당함.
- 현재 `hand_grasp` reward/action/observation은 이 계획을 기록하는 동안 변경하지 않음.

## Collision/valley 자동 기록 probe

- `scripts/debug/hand_grasp_collision_probe.py`를 추가함. 학습 policy를 로드하지 않고 항상 1 env로
  `stick1`–`stick2` 닫힘 각도 sweep과 `stick2`–엄지/검지 valley 위치 sweep을 수행함.
- contact sensor는 학습 observation/reward가 아니라 **probe 측정 전용**임. 거리만으로 구분할 수 없는
  실제 물리 접촉, 떠 있음, 관통 후 solver에 밀려남을 접촉력·접촉점·변위·속도로 구분하기 위해 사용함.
  센서는 실행 시 임시 `env_cfg`에만 붙으므로 active `hand_grasp` cfg 파일과 학습 비용은 변하지 않음.
- stick-pair sweep은 `0,2,4,5,6,8°`에서 접촉력, 평균 접촉점의 `stick2` local y,
  근사 tip gap과 한 physics step 뒤 변위를 기록함. 현재 의미상 local `−y`가 tip이며,
  첫 접촉이 설정된 tip 구간에서 발생하는지를 판정함.
- valley scan은 `palm_link`, 엄지/검지 base와 middle link를 `stick2`로 필터링함.
  엄지 base 관절과 palm-frame `x/z` 위치를 coarse sweep하고 실제 anchor 접촉,
  release 뒤 변위·최종 속도를 기록함. 약지 지지가 없는 geometry feasibility screen이므로
  이 결과만으로 안정 파지 성공을 선언하지 않음.
- 각 실행은 자동으로
  `logs/debug/hand_grasp_collision_probe/<timestamp>/` 아래
  `probe.log`, `config.json`, `pair_sweep.csv`, `valley_scan.csv`, `summary.json`을 저장함.
  실행은 사용자가 담당하며 완료 통보 후 저장된 최신 `summary.json`과 CSV를 판독함.
- 시뮬레이션은 실행하지 않았고 `py_compile`과 `git diff --check`만 통과함.

- 26번은 `q_thumb=(0.0, 0.4)`, palm-frame offset `(5, -10) mm`에서
  `index_base + thumb_mid + index_mid` 접촉이 발생했지만, release 뒤 0.05초 동안 막대가
  `3.91 cm` 이동했으므로 안정 valley 후보가 아님. palm-only는 valley 성공으로 인정할 수 없음.
- stick pair는 4도부터 tip 구간 contact point가 생성됐지만 기존 1-step force-only 판정에서는
  peak force를 놓쳐 전체 CHECK가 됨. 재검증본은 여러 physics step의 peak force를 모으고,
  force와 별개로 contact point 생성 여부를 기록함.
- valley 성공조건을 `thumb-side 접촉 AND index-side 접촉 AND displacement <= 2 mm
  AND final speed <= 0.05 m/s`로 수정함. 모든 후보의 YES/NO를 출력하므로 palm-only가
  성공처럼 보이지 않음. settle은 6→12 physics step으로 늘림.
- 살짝 닿은 막대가 튀는 현상은 10 g 막대를 접촉/침투 위치에 즉시 놓은 뒤
  `max_depenetration_velocity=5 m/s`로 침투를 해소하는 설정과 일치함. 실제 첫 probe에서도
  최대 `5.049 N`, `0.149 m/s` 후보와 수 cm 이상 밀려나는 후보가 관측됨.
- `hand_grasp` 한정으로 손과 두 막대 collider의 `contact_offset=1 mm`, `rest_offset=0`,
  `max_depenetration_velocity=0.2 m/s`를 명시하고 velocity solver iteration을 1→4로 올림.
  접촉 impulse 상한은 파지력까지 제한할 수 있어 이번 수정에서는 건드리지 않음.
- 수정본은 정적 compile을 통과했으며 런타임 재검증은 사용자가 같은 probe를 다시 실행한 뒤 판정함.
  재검증 전에는 valley pose나 IK 기준 자세를 확정하지 않음.

## Valley 재판정과 자동 2-stick IK/contact 탐색

- 수정 probe `2026-07-27_16-19-09`에서 contact sensor는 정상 작동했음.
  120개 중 `palm` 단독 100개, `palm + thumb_mid` 19개, 무접촉 1개였고 index 접촉은 0개였음.
- 기존 `thumb-side AND index-side` 필수 판정은 실제 valley anchor보다 엄격했음. ContactSensor는
  link 내부 특정 깊이에 달린 점 센서가 아니라 link collision mesh 전체 접촉을 측정함.
  현재 index는 default open pose라 7 mm stick이 골 안에 있어도 index collider에 하중이 없을 수 있음.
- valley probe의 **단측 anchor screen**을 `palm contact + thumb/index 중 한 side contact
  + displacement <= 2 mm + speed <= 0.05 m/s`로 정정함. 동시 index 접촉은 diagnostic으로 남김.
  이 임시 기준으로 기존 로그의 36, 37, 51번을 IK 위치 seed로 사용했고, 36번이 최소 변위
  0.81 mm였음. 단, 세 후보 모두 `two_sided_valley_contact=False`, `feasible=False`이므로
  표준 젓가락 파지가 성립했다는 의미는 아니며 이후 CEM에서 위치 범위를 다시 확장함.
- `scripts/debug/hand_grasp_ik_search.py`를 추가함. 수동 키보드 관절 조정을 주 탐색으로 쓰지 않고,
  기본 512개 env의 batched FK와 CEM으로 Wuji finger1~4의 16개 관절 후보를 자동 탐색함.
- 고정 pose는 Stick2=valley 36번, Stick1=tail-side pivot 기준 5도 닫힘(tip-first 접촉)으로 구성함.
  기하 목적은 엄지·검지·중지 tip→Stick1, 약지 tip→Stick2, thumb middle proxy→Stick2임.
- 자동 탐색기 첫 작성에서 isolated world pair의 `+x` 간격을 palm `+x`에 그대로 넣어,
  `palm +x = world +z`인 현재 손 배치에서 두 stick이 위아래로 쌓이는 축 변환 오류가 있었음.
  실행 전에 Stick1 중심 간격을 `palm +z = world +x`로 수정하고 닫힘 회전도
  palm `x`축(=world `z`축) 5도로 바꿈. 따라서 손가락 진행 방향 world x에서 Stick1/2가 갈라지고
  손가락을 굽히면 tip이 서로 닫히는 배치임.
- fingertip link origin 대신 실제 collision mesh가 주로 local `-z`로 뻗는 길이를 반영한 pad proxy를
  사용함. stick 표면 거리와 끝단 회피를 점수화하고, 전체 관절 pose를 하드코딩하지 않음.
- 상위 기본 16개 후보는 손가락 목표를 90 physics step 동안 점진적으로 닫은 뒤 두 dynamic stick을
  240 step(2초) 자유롭게 둠. 이때 필수 contact fraction, link별 peak force, stick1-stick2 첫 접촉
  local y/region, pair peak force, 두 stick 최대 속도·변위·낙하, joint tracking error를 저장함.
- 안정 후보는 stick pair 첫 접촉이 `none/tip`, pair peak force 5 N 이하, 각 stick 최대 속도

  수치 기준은 첫 결과를 보고 강화하며, 이번 단계 출력만으로 최종 q_ref를 확정하지 않음.
- 실행 결과는 `logs/debug/hand_grasp_ik_search/<timestamp>/`의 `probe.log`, `config.json`,
  `ik_candidates.csv`, `validation.csv`, `summary.json`에 자동 저장함.
- 정적 compile만 통과했으며 시뮬레이션 실행은 사용자가 담당함. 성공 후보가 나온 뒤에만 GUI로
  상위 후보를 육안 확인하고 필요하면 미세조정함.

## Simulation-only 2-stick pre-grasp 탐색 완료

### 무엇을 찾은 것인가

- 이번 탐색의 결과는 force-closure가 끝난 최종 파지나 2초 release-stable 자세가 아니라,
  **지정한 젓가락 topology에 손가락을 수 mm까지 접근시킬 수 있는 nominal pre-grasp**임.
- topology는 끝까지 고정함.
  - 노란 위쪽 `stick1`: 엄지·검지·중지 fingertip.
  - 초록 아래쪽 `stick2`: 약지 fingertip, palm, 엄지 중간마디.
  - 새끼는 이번 후보 탐색에서 자유.
- 파지 개구부 법선, virtual cage, 실물 관절각 측정은 사용하지 않음. 손/스틱 pose, 접촉점 후보,
  관절각을 모두 시뮬레이션 내부의 Wuji FK와 PhysX로 찾음.

### 자동 탐색·디버그 절차

1. **축과 초기 물리 배치 확인**
   - palm local `+x`가 world `+z`인 실제 palm-up 배치를 기준으로 삼음.
   - 두 stick 장축은 world `+y`, 두 stick의 손가락 진행 방향 간격은 palm local `+z`
     (=world `+x`)로 정의함.
   - `7 x 180 x 7 mm`, 10 g stick이 얕은 침투에서 튀지 않도록 contact offset 1 mm,
     max depenetration velocity 0.2 m/s, velocity solver iteration 4를 사용함.

2. **stick-stick 및 valley collision probe**
   - `hand_grasp_collision_probe.py`로 stick pair 닫힘 각도 `0,2,4,5,6,8°`를 sweep함.
   - 5°에서 첫 접촉이 handle이 아니라 tip 구간에 생기는 것을 확인함.
   - valley 위치 120개를 sweep해 contact actor, force, contact point, release 변위·속도를 기록함.
   - 36/37/51번은 palm+thumb-mid 단측 지지와 작은 변위를 보여 초기 IK seed로 사용했지만,
     모두 index-side contact가 없어 최종 valley/표준 파지 성공으로 보지 않음.

3. **4096-env batched FK+CEM**
   - `hand_grasp_ik_search.py`가 finger1~4의 16관절을 10% joint-limit margin 안에서 병렬 탐색함.
   - fingertip link origin이 아니라 collision mesh 끝의 pad proxy를 사용함.
   - 목적함수는 각 proxy에서 담당 stick **표면까지의 거리**를 사용하므로 한 점을 하드코딩하지 않음.
   - stick 끝단 밖으로 벗어나는 해, fingertip끼리 같은 점으로 겹치는 해, joint limit에 붙는 해를
     각각 axial/overlap/joint barrier로 억제함.
   - 처음 25 iteration은 teleported FK로 기구학을 빠르게 탐색하고, 마지막 10 iteration은
     proximal `joint1/2`와 distal `joint3/4`를 단계적으로 구동하는 actuator-aware rollout으로 전환함.
     CEM 단계는 각 stage `24 ramp + 72 settle`, 최종 검증은 `60 ramp + 120 settle`을 사용함.

4. **자유 rigid-body 물리 검증**
   - 상위 16개 후보의 stick을 목표 palm-relative pose에 놓고 손을 단계적으로 닫음.
   - 이후 stick을 240 physics step(2초) 동안 release하여 contact fraction, stick 변위/속도,
     stick-stick 첫 접촉 구간·힘, joint tracking, torque clipping을 저장함.
   - 이 엄격한 `stable` 판정은 최종 force-closure screen이며 pre-grasp 채택의 필수조건으로
     해석하지 않음.

5. **self-collision A/B**
   - 같은 후보를 self-collision ON/OFF로 각각 별도 Isaac 프로세스에서 replay함.
   - ON: median tracking `0.554 rad`, 평균 네 fingertip 거리 `50.1 mm`.
   - OFF: median tracking `0.295 rad`, 평균 네 fingertip 거리 `39.0 mm`.
   - 특히 OFF에서 검지·중지·약지 `joint1/2` tracking이 거의 0으로 줄어,
     self-collision이 실제 접근 경로를 막는 한 원인임을 확인함.
   - 다만 OFF에서도 처음에는 검지/중지/약지가 12~16 mm에서 정체했으므로
     self-collision만 고치면 끝나는 상태는 아니었음.

6. **병목 변수를 한 단계씩 해제**
   - Stick1 상대 중심 간격을 `9~30 mm`, close angle을 충돌 없는 tip-touch 범위에서 CEM 변수로
     만들었지만 run `2026-07-27_17-50-01`의 FK 오차는 여전히 약
     `12/13/16 mm`였음. 따라서 기존 `20 mm/5°` 가정은 주 병목이 아니었음.
   - 동시에 Stick2 palm-normal 위치가 매번 기존 상한 `16.33 mm`에 붙고,
     검지·중지·약지 관절도 10% flexion 상한에 붙는 것을 확인함.
   - 초기 valley 36번이 양측 파지가 아니라 단측 palm+thumb anchor였다는 사실과 합쳐,
     Stick2 palm-normal 탐색 범위를 `11.3~16.3 mm`에서 `11.3~36.3 mm`로 확장함.
