### (c) — `BalancedObjectOrientationCoupledReward`의 best 갱신 방식
- before: `self._best_error = torch.where(active, min(best, ori), best)` (goal 안에서만 갱신)
- after: `self._best_error = torch.minimum(self._best_error, orientation_error)` (안·밖 모두 갱신)
- 지급은 여전히 `active`(goal 안 + gate)에서만.
- 근거: best가 밖에서 얼어붙어 있으면 "밖에서 회전 개선 → best에 저장 → 재진입 때 (best−현재) 인출"
  왕복 파밍(진동)이 가능했음. best를 밖에서도 내려가게 하면 재진입 progress=0 → 인출 차단.
  개선 회전을 **goal 안에 머문 채** 해야만 지급됨.
- ⚠ (c)는 진동/exploit를 닫는 것이지 error max를 직접 줄이지 않음. 판정은 success rate와
  15°미만 비율로 볼 것(평균 낮추기 ≠ 임계 통과). (c) 후에도 안 내려가면 도달성이 병목.

## 코드 수정 — 말단 정밀 수렴 지수 커널 (chopstick) + 페널티 3종 (box·chopstick)

### 지수 커널 (chopstick_mdp_cfg.py, weight 0 기본 — 튜닝 후 켤 것)
선형 보상이라 말단(goal 코앞)에서 당기는 힘이 약한 걸, e=0에서 기울기 최대인 `exp(-e/σ)`로 보강.
pos·ori를 곱커널로 엮지 않고 **분리**(한 축 막혀도 다른 축 refine + 진단성). 형태는 Gaussian이 아니라
**Laplacian `exp(-e/σ)`**(0에서 기울기 최대라 말단 조임에 맞음).
- `FineProximityReward` (position): `gate × exp(-d/σ_d)`, best-so-far. σ_d=0.02(2cm, <5cm success).
- `FineOrientationReward` (orientation): `gate × exp(-θ/σ_θ)`, θ=stick_tip_ori_error(4-대칭), best-so-far,
  **pos<3cm & gate일 때만**(드리프트 차단) + (c) best 안·밖 모두 갱신(왕복 인출 차단). σ_θ=0.1745(10°, <15°).
- 초기값 고려: ① baseline은 잡은-채-근처 첫 스텝에 seed ② **σ<success 임계**(임계 안쪽 refine)
  ③ 너무 뾰족하면 sparse-like라 학습 어려움 → 넉넉히 시작 후 필요시 σ 축소(커리큘럼).
- coarse(transport φ + lift)는 유지 — "모양의 사다리"(reciprocal/선형 접근 → exp 말단).

### 페널티 3종 (box_mdp_cfg.py + chopstick_mdp_cfg.py 양쪽)
뉴로메카 예제 함수 사용:
- `end_effector_speed` weight **-0.001**: EE(palm_link) 선속도 L2. 급격한 팔 이동 억제.
- `action_rate` weight **-0.005 → -0.001**: 이전-현재 action 차 제곱합.
- `action_second_rate` weight -0.0001: **비활성(주석)** — 함수가 `# TODO: currently broken` 상태.
- ⚠ box도 reward 구조 변경됨 → box 다음 run은 fresh 필요. (도는 box run은 메모리 로드라 무영향.)

## 코드 수정 — Box-Transport에 SimToolReal keypoint 방식 구현 (chopstick과 A/B)

SimToolReal(arXiv:2602.16863) Eq.2의 keypoint 목표 도달 보상을 **box에** 구현. chopstick은
쿼터니안 4-sym + exp 커널 유지 → **box(keypoint) vs chopstick(쿼터니안) 비교** 목적.

### 방식 (Eq.2)
- `d = maxᵢ‖oₜ,ᵢ − gᵢ‖` : 대칭최소 **max 꼭짓점 거리**(8 corner, `square_prism_y` 8-sym 최소).
  max라 **모든 꼭짓점이 가까워야** d 줄어듦 → **pos·ori 구조적 결합**(한 축만 맞추고 드리프트 불가).
- `r_goal = gate × max(d_best − d, 0)` : best-so-far(d_best=지금까지 최소), 왕복/캠핑 파밍 없음.
- 성공: `d < keypoint_eps` + gate 0.5s 유지. success bonus는 transport_success(+1000)가 담당.

### 바꾼 곳
- `mdp/rewards.py`: `square_prism_keypoint_goal_distance`에 **`reduce="max"` 옵션** 추가(기본 mean, 기존 무영향).
- `box_mdp_cfg.py`:
  - 신규 클래스 `KeypointMaxGoalProgressReward`(dense) + `KeypointMaxAtGoalHeld`(success).
  - `keypoint_goal` RewTerm **weight 8000**(활성). ⚠ d가 m 단위라 φ와 스케일 달라 **weight 튜닝 대상**.
  - `cube_transport` 8000→**0**, `box_orientation` 4000→**0** (복구용 유지).
  - `success` func: `BalancedObjectAtGoalHeld`(pos<5cm+ori<15°) → **`KeypointMaxAtGoalHeld`**(keypoint_eps=0.05).
    복구용 기존 파라미터 주석 보존.
- grasp shaping(reach/hold/grip)·lift·페널티 3종은 유지 = SimToolReal의 r_grasp+r_smooth에 대응.

### 비교 설계 (A/B)
- **box**: SimToolReal keypoint(max 꼭짓점, pos·ori 융합). 8-sym(균일 스틱).
- **chopstick**: 쿼터니안 4-sym(tip/tail) + coupled + (c) + exp 말단 커널(weight 0). 
- 둘 다 grasp shaping·penalty·lift 공통. 목표 도달 항만 다름.

### 주의 (탐색)
- SimToolReal은 SAPG(PPO 변종)+asymmetric critic로 **탐색 병목**을 뚫음. 우리는 standard PPO(rsl_rl)라
  keypoint여도 **updown/local optimum에 막힐 수 있음**. 필요 시 goal 커리큘럼·entropy·mean초기 등 탐색 보조.
- ⚠ box reward 구조 전면 변경 → **box 다음 run은 완전 fresh**. 스모크 미실시(학습 중). obs는 73 불변(reward만).

## 정정 — Box keypoint를 full-pose(8-corner + roll 4-sym)로 확정

위 SimToolReal keypoint 구현 후 "2점(tail/tip)"으로 갔다가 다시 **8-corner full-pose로 되돌림**.
- **왜 2점을 뺐나**: 2점(장축 위)은 **roll을 통째로 무시**하는데, 정사각 스틱은 roll이 **90°만 대칭** →
  45° 굴린 자세가 다른 pose인데 2점은 성공 처리(under-constrained). 사용자 지적("성공하려면 pose 다 맞춰야지").
  2점은 **원형 스틱**(roll 연속 대칭)에서만 맞음 → `_stick_tail_tip_pose_error`는 미사용/보존.
- **최종 box 목표항**: `d = square_prism_keypoint_goal_distance(..., symmetry="square_prism_y_tip", reduce="max")`.
  - **8-corner max 거리** → 모든 꼭짓점(옆면 포함)이 가까워야 → 위치+자세(roll 포함) **full 매칭**.
  - 대칭 **`square_prism_y_tip` = roll 4-대칭(0/90/180/270°, flip 제외)** → tail/tip 구분 + 45° roll 오답.
- `rewards.py`: `square_prism_keypoint_goal_distance`에 `"square_prism_y_tip"`(4-sym roll) 옵션 추가.
- `keypoint_goal` w8000 / cube_transport·box_orientation·**goal_proximity 0**(위치-only 연금 파밍 방지, 사용자 최종안) /
  success=`KeypointMaxAtGoalHeld`(8-corner max < eps 0.05 + gate 15스텝).
- A/B: **box=8-corner full-pose keypoint(roll 4-sym) MAX best-so-far ∥ chopstick=쿼터니안 4-sym+exp.**
  둘 다 full pose(roll 포함) 요구, 측정 방식만 다름. weight 8000·eps 0.05는 시작값(d가 m 단위, 튜닝).
