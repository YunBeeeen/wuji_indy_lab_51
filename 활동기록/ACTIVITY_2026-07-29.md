## tip gap 정의 교정

### 기존 식의 문제

기존 gap은 두 distal endpoint 중심의 3D L2 거리에서 고정 두께 7 mm를 빼는 단순 proxy였음.

```text
gap_old = max(||p1_tip - p2_tip||₂ - 0.007, 0)
```

이 식은 다음을 구분하지 못함.

- 두 stick이 장축 방향으로 엇갈려 tip 중심이 멀어진 것
- square cross-section이 회전해 분리방향으로 보이는 반폭이 달라진 것
- 실제 OPEN/CLOSE에 해당하는 장축 수직 방향의 표면 간격

### 새 식

1. 각 stick local `+y`의 `0.09 m` distal endpoint를 tip center로 계산함.
2. 두 local `+y` 장축의 부호를 맞춘 뒤 평균해 공통 장축 `a`를 구함.
3. tip-center 차벡터 `Δp`에서 장축 성분을 제거함.

```text
Δp_perp = Δp - (Δp·a)a
d_perp  = ||Δp_perp||₂
n       = Δp_perp / d_perp
```

4. 각 사각 단면의 local `x/z`축을 현재 자세로 회전시킨 뒤 분리방향 `n`에 대한 support radius를
   계산함. 반두께는 `h=3.5 mm`임.

```text
r_i = h (|n·x_i| + |n·z_i|)
gap = max(d_perp - r_1 - r_2, 0)
```

- 이 계산은 고정 palm normal이나 과거 파지 개구부 추정 법선을 사용하지 않음.
- 동일 `_tip_surface_gap()`이 OPEN/CLOSE reward, mode stability, success hold,
  TensorBoard `tip_surface_gap/tip_gap_error`에 모두 사용됨.
- 두 stick이 크게 비평행해지는 상태의 완전한 box-box 최단거리 계산은 아니지만, Stick2 pose와
  Stick1 pivot 및 6접촉을 함께 유지하는 현재 제어 범위에서는 장축 slip과 단면 회전 편법을 제거한
  일관된 opening coordinate임.

## 연속 OPEN/CLOSE 회복 학습 구조

- OPEN `20 mm`, CLOSE `3 mm`로 되돌림.
- command는 reset에서만 50:50으로 초기화하고, 이후 3초마다 현재 one-hot의 반대 mode로 토글함.
  독립 랜덤 재추첨이 아니므로 OPEN과 CLOSE가 반드시 번갈아 나옴.
- episode를 `16→30 s`로 늘림. 한 episode에는 약 10개의 3초 mode 구간과 9회의 전환이 들어감.
- 성공은 episode termination이 아니라 mode interval당 한 번의 `+30000` one-shot reward임.
  command가 바뀌면 stable-step과 awarded latch를 다시 초기화함.
- termination의 success term은 canonical metric을 위해 남기되 `hold_steps=1,000,000`으로 만들어
  실제 종료시키지 않음. 두 stick 중 하나의 height가 `0.40 m` 아래로 내려가면 즉시 drop 종료하고,
  그렇지 않으면 30초 timeout에서 reset함.
- active mode success는 다음을 동시에 30 policy step, 즉 1초 유지해야 함.
  - active gap error `≤3 mm`
  - Stick1 in-hand pivot error `≤15 mm`
  - Stick2 palm-relative position/orientation error `≤20 mm/20°`
  - 6 semantic contact force 모두 `≥0.02 N`
  - 두 stick 최대 선속도 `≤0.15 m/s`
  - 두 stick 최대 각속도 `≤3 rad/s`

### 현재 reward

```text
joint reference                         weight  2
Stick1 in-hand pivot                    weight 10
Stick2 palm-relative reference pose     weight 15
active OPEN gap exp(-|g-0.020|/0.005)  weight 20
active CLOSE gap exp(-|g-0.003|/0.005) weight 20
minimum of six contact strengths        weight 20
6-contact × quiet × active-gap          weight 50
angular speed excess over 3 rad/s       weight -0.1
mode success one-shot                   weight 30000
action rate                             weight -0.001
```

- 6 semantic contact는 Stick1의 thumb distal(`finger1_link3`), index tip, middle tip과
  Stick2의 palm, thumb middle(`finger1_link2`), ring tip임.
- 접촉별 큰 독립 reward 경쟁 대신 여섯 접촉의 minimum과 full-contact stability를 사용하므로,
  다섯 접촉을 세게 누르고 하나를 버리는 해가 다른 힘으로 보상되지 않음.
- Stick1 full pose를 고정하지 않고 손 안쪽 pivot만 고정해 distal tip의 시소형 open-close 회전을 허용함.
  Stick2는 아래쪽 기준 rail로 palm-relative full pose를 유지함.

## hand_grasp — residual action 판독과 palm-relative 속도 전환

### residual action 판독

- 이전 고정-reference action은 모든 관절의 PD target을
  `q_reference + 0.1 * clip(action, -1, 1)`로 만들었으므로 각 관절의 전체 도달 범위가
  reference 기준 `±0.1 rad`로 제한됐음.
- 현재 action은 `q_current + 0.1 * action`이므로 여러 policy step에 걸쳐 관절을 joint limit까지
  이동할 수 있음. `10 s` episode와 `5 s` mode dwell 변경도 함께 적용되어 OPEN/CLOSE 이동과
  30-step 안정화 시간이 늘어남.
- 각속도 페널티가 있던 `16-24-00`이 제거한 `17-25-14`보다 양호했고, 제거 run도 일정하게
  개선되지 않았음. 단일 seed라 학습 운과 항 자체의 효과를 분리할 수는 없지만, 페널티가
  OPEN/CLOSE 수렴의 주 병목이라는 근거는 나오지 않음. 현재 기준에서는 각속도 페널티를 유지함.

### 복구한 각속도 페널티

- 두 stick 중 더 빠른 각속도에 대해
  `-0.1 * clip(max(||ω1||, ||ω2||) - 3, 0, 10)^2`를 독립적으로 적용함.
- `3 rad/s` 이하는 음수 페널티가 없고, mode stability는 별도로
  `exp(-linear_speed / 0.1 - angular_speed / 2)`를 사용함.
- mode success는 6개 contact·geometry와 함께 선속도 `≤0.15 m/s`,
  각속도 `≤3 rad/s`를 30 policy step 유지해야 함.

### palm-relative 속도로 통일

- 향후 floating hand가 stick을 안정적으로 들고 함께 이동·회전할 때 world 속도를 파지 불안정으로
  오판하지 않도록 reward, success gate, TensorBoard 진단 속도를 모두 palm-relative로 변경함.
- 상대 속도 정의:
  - `ω_rel = ω_stick - ω_palm`
  - `v_rel = v_stick - v_palm - ω_palm × (p_stick - p_palm)`
- 변경 대상:
  - 독립 `object_pair_angular_speed_excess_l2`
  - `mode_grasp_stability` 내부의 선속도·각속도 shaping
  - `OpenCloseModeHeld`의 30-step success 속도 조건
  - `Metrics/hand_grasp*`의 stick/max linear·angular speed와 `quiet_valid`
- 기존 observation의 두 stick velocity 12D는 이미 같은 palm-relative 정의를 사용하고 있었음.
- palm이 고정된 현재 OPEN/CLOSE 환경에서는 palm 속도가 거의 0이므로 기존 world 기준과 수치가
  사실상 같음. 따라서 `16-24-00`은 고정-palm baseline으로 계속 유효하며, 이 변경만을 이유로
  폐기하거나 재학습할 필요는 없음. 이미 실행 중인 process에는 반영되지 않고 fresh run부터 적용됨.
- relative 속도가 항상 더 작은 것은 아님. stick이 움직이는 palm을 따라오지 못하거나 손 안에서
  미끄러지면 상대 속도가 커져 의도대로 페널티와 success 실패가 발생함. OPEN/CLOSE로 Stick1이
  palm에 대해 실제 회전하는 동안에도 `3 rad/s` 초과분은 그대로 제어됨.

## hand_grasp — distal tip lateral alignment gate

- play에서 두 distal tip의 장축 방향 엇갈림은 작지만 Stick1이 Stick2 옆으로 빗겨나간 채 radial
  gap만 맞추는 경우를 확인함. obs를 늘리지 않고 reward/success용 privileged geometry만 보완함.
- `pose_005`의 tip separation을 Stick2 local x-z 평면에 투영·정규화한 방향
  `n_ref=(0.887693, 0, -0.460435)`을 기준으로 사용함. 이는 검증된 파지의 상대 방향이며

  기준 방향에 수직인 성분을
  `e_lat=|(-n_z, n_x)·(delta_x, delta_z)|`로 계산함.

  lateral reward는 추가하지 않아 옆 정렬만 유지하며 reward를 farming할 수 없게 함.

  이 과정에서 diagnostic의 `tip_surface_gap`이 예전 `3D center distance - 7 mm` 식에 남아 있던
