## 2. `hand_setting` 손가락 경로 보완

- 관절별 best-so-far 구조는 유지하되, 새끼가 약지보다 먼저 닫혀 약지의 Stick2 접근
  경로를 막는 현상을 줄이기 위해 새끼 Joint1~4의 progress credit만 `0.25`로 낮췄다.
  검지·중지·약지는 각각 `1.0`이며, 내부에서 weight 합으로 정규화하므로 term 전체의
  최대 reward budget은 변하지 않는다.
- 새끼는 제거된 것이 아니다. all-20 reference prior와 Stage-2의 all-joint `5 deg`
  hard gate에는 계속 포함된다.
- Stage 1을 한 번 통과한 뒤 다음 semantic surface 접근 신호를 약하게 추가했다.

```text
index tip  -> Stick1 box surface
middle tip -> Stick1 box surface
ring tip   -> Stick2 box surface

score_i = clip(1 - surface_distance_i / 0.08, 0, 1)
raw = 0.5 * mean(score_i) + 0.5 * min(score_i)
weight = 2
```

- 이 항은 best-so-far가 아니라 현재 거리 기반 live restoring signal이다. q-reference를
  따라가다 지정 stick에서 멀어지면 즉시 손해를 보고 다시 접근하면 회복한다.
- Stage 1은 one-way unlock으로만 사용한다. 접촉 때문에 live Stage-1 gate가 잠깐 꺼져도
  접근 유도가 갑자기 사라지지 않는다.
- 이는 관측을 추가하지 않는 학습용 shaping이다. `hand_setting`은 계속 obs/action
  `101D/20D`이며 Stage-2 contact mean/min은 아직 주석 상태다.

## 3. 수동 play와 손 링크 접촉력 진단

- play에서 `functional_contact_lost` termination만 자동으로 끈다. 접촉이 5개 이하로
  내려가도 정책의 복구 동작을 계속 볼 수 있으며, 물리적 drop·floor·timeout 등 다른
  termination은 유지한다.
- 수동 전용 `hand_play`는 OPEN으로 시작하고 stick disturbance를 비활성화하며 episode를
  `300 s`로 둔다.
- viewport 단축키 충돌을 피하도록 회전 키를 다음으로 확정했다.

```text
rotation: A/S = roll, D/Z = pitch, X/C = yaw
translation: arrows + PageUp/PageDown 또는 I/K, J/L, U/O
mode: 1 = OPEN, 2 = CLOSE
```

- `play.py`에 손 전체 링크의 PhysX contact force를 보는 두 진단을 추가했다.
  - `--show_hand_contact_forces`: viewport 화살표와 터미널 값
  - `--plot_hand_contact_forces`: 별도 PySide6 + pyqtgraph 프로세스의 실시간 그래프
- 센서는 진단 옵션을 켰을 때만 palm/finger rigid body 전체에 동적으로 추가된다.
  각 곡선은 해당 링크가 받은 world-frame net contact-force vector의 크기다. actuator
  torque나 root-PD wrench가 아니며, 그래프의 `sum |F_link|`는 벡터합이 아니라 링크별
  크기의 스칼라 합이다.
- 외부 그래프는 bounded queue를 사용해 GUI가 느려져도 physics loop를 block하지 않는다.
  기본 history/telemetry는 `10 s/20 Hz`다.
- 사용자가 reset 파지에서 확인한 대략적인 값은 palm 약 `3 N`, `finger1_link2` 약
  `2.5 N`, 나머지 finger link 대부분 `0~1 N`이었다. 이는 현재 simulator contact의
  관측값이며 실물 센서 기준값으로 확정하지 않는다.

## 4. sim-to-real용 `hand_real` 신설

- `hand_move`의 scene, reset, floating-root controller, 20D current-joint residual action,
  OPEN/CLOSE command, reward, termination, disturbance를 그대로 상속하는 별도 task
  `hand_real`을 추가했다.
- policy observation만 simulator velocity 없이 다음 `105D`로 교체했다.

```text
joint position history       40 = q_(t-1), q_t (20 + 20, joint-limit normalized)
current fingertip positions  15 = five palm-frame xyz values
Stick1 pose history           14 = pose_(t-1), pose_t (xyz + wxyz)
Stick2 pose history           14 = pose_(t-1), pose_t (xyz + wxyz)
last executed action          20
OPEN/CLOSE mode                2
total                        105
```

- joint velocity와 Stick의 선속도·각속도는 actor observation에 없다. 정책은 연속된
  position/pose 두 샘플로 motion을 추론한다.
- Isaac Lab observation history는 oldest-to-newest이므로 각 history term은
  `[previous, current]` 순서다. reset 직후에는 두 슬롯이 reset sample로 채워져 가짜
  zero pose를 넣지 않고 zero motion을 표현한다.
- Stick quaternion은 `w >= 0`인 canonical `wxyz`로 변환해 동일 회전의 `q/-q` 부호
  전환이 큰 가짜 temporal jump를 만들지 않게 했다.
- action history는 `ActionManager.prev_action`이 아니라 `ActionManager.action`을 쓴다.
  post-step observation 기준으로 이것이 현재 상태를 만든 직전 실행 action이며,
  `prev_action`을 쓰면 한 policy step 더 오래된 값이 들어간다.
- fingertip position은 실물에서 encoder 기반 FK로 계산하고, 두 Stick pose는 추후 vision이
  palm frame `xyz+wxyz`로 공급한다고 가정한다. real controller도 학습과 같은 joint 순서,
  joint limit normalization, quaternion convention, 고정 policy 주기(현재 30 Hz)를 지켜야 한다.
- reward/termination에서 simulator contact나 velocity를 사용하는 것은 허용한다. 이것들은
  학습 신호일 뿐 actor observation이나 실물 policy 입력이 아니다.
- task ID와 RSL-RL experiment name은 모두 `hand_real`로 분리했다.
- `hand_move` 체크포인트는 `103D`, `hand_real`은 `105D`라 직접 load할 수 없다.
  action이 같아도 actor input shape가 다르므로 `hand_real`은 fresh 학습한다.

## 7. `hand_setting` Stage-2 조기 contact shaping

- run `2026-08-10_18-30-36` iteration 1656에서 Stage-1 평균/final은
  `0.736/0.896`이지만 all-joint max reference error가 평균/final
  `1.603/1.329 rad`라 strict `5 deg` Stage-2는 계속 0이었다.
- strict `stage2_ready`는 그대로 유지하고 functional-contact mean/min을 관절 RMSE에 따라
  점진 활성화했다.

```text
progress = stage1_ready * clip((0.80 - q_RMSE) / (0.80 - 0.0873), 0, 1)
contact mean/min weight = 5 / 20, force scale = 0.10 N
```

- 현재 RMSE 약 `0.67 rad`에서는 Stage-1 유효 시 약 18%만 켜진다. TensorBoard에
  `stage2_contact_progress`를 추가했다. 검지의 between-sticks 조건은 아직 넣지 않았으며,
  먼저 6-contact가 자연스럽게 올바른 삽입을 만드는지 확인한다.
